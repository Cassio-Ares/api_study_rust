# Tests

| Macro | Quando usar |
|---|---|
| `#[test]` | Função síncrona simples |
| `#[tokio::test]` | Função async (banco, HTTP) |
| `assert!` | Verifica se condição é `true` |
| `assert_eq!` | Verifica se dois valores são iguais |
| `assert_ne!` | Verifica se dois valores são diferentes |
| `assert!(x.is_ok())` | Verifica se `Result` é `Ok` |
| `assert!(x.is_err())` | Verifica se `Result` é `Err` |
| `assert!(x.is_some())` | Verifica se `Option` tem valor |
| `assert!(x.is_none())` | Verifica se `Option` é vazio |

- Neste projeto só foi feito teste de integração 

* Teste de Repository -> Testa se o SQL está correto e se o mapeamento para a Struct funciona.

* Teste de Service -> Testa Lógica de Negócio, mas como ele também chama o banco, ele acaba sendo um teste de integração "mais largo".

OBS: Neste projeto os testes parecem similares porque, nesta fase inicial da API,
o Service ainda não tem "muito o que fazer" além de chamar o Repository.


## Conexão com banco de dados

Limpeza manual
No caso setup_test_db, limpa a tabela antes de cada teste.

````
use sqlx::PgPool

// Função auxiliar compartilhada entre todos os testes
// Não é um teste em si — é a infraestrutura dos testes

async fn setup_test_db()-> PgPool{
  // Lê a URL do banco de TESTE — separado do banco de produção!
  // .env deve ter DATABASE_TEST_URL apontando para outro banco
  let database_url = std::env::var("DATABASE_TEST_URL")
        .expect("DATABASE_TEST_URL must be set");
  
  // Conecta ao banco de teste
  let pool = PgPool::connect(&database_url)
    .await
    .expect("Failed to connect to Postgres for testing.");


  // Execute as migrations - garante que as tabelas existem
  // "./migrations" = pasta com os arquivos SQL de criação de tabelas  
  sqlx::migrate!("./migrations")
        .run(&pool)
        .await
        .expect("Failed to run migrations for testing.");

    // ✅ MUITO IMPORTANTE — limpa o banco ANTES de cada teste
    // TRUNCATE = apaga todos os dados da tabela
    // RESTART IDENTITY = reseta os IDs sequenciais para 1
    // CASCADE = apaga também dados de tabelas relacionadas
    // Garante que cada teste começa com banco limpo e isolado
    sqlx::query("TRUNCATE TABLE payments RESTART IDENTITY CASCADE")
        .execute(&pool)
        .await
        .expect("Failed to clean database before tests");

    pool // retorna o pool pronto para uso no teste
} 
````

- Como tanto repository_test como service_test vão usar conexão com banco o "setup_test_db" 
vai ser posto em um arquivo common.rs (Que vai ser como um utils ou helper e vai carregar funções, variaveis e ...
que são comuns entre os testes)

````
// importes
use crate::common::setup_test_db;
use crate::repository::payment_repository;
use crate::model::payment::{NewPayment, Payment, PaymentMethod, PaymentStatus};
use uuid::Uuid;
use validator::Validate;

// #[tokio::test] -> macro que transforma uma função async em um test que
// o rust consegue executar, sem ela a função async não rodam como testes

#[tokio::test]
async fn test_create_payment(){
  let pool = setup_test_db().await; //banco limpo

  // Monta o dado de entrada do teste
    let new_payment = NewPayment {
        amount: 150.0,
        currency: "USD".to_string(),
        payment_method: PaymentMethod::CreditCard,
        payment_reason: "Test Payment".to_string(),
        status: PaymentStatus::Completed,
    };

    let payment = payment_repository::create_payment_repository(
      &pool,
      new_payment
    )
    .await
    .unwrap(); // unwrap → se der Err o teste falha com a mensagem do erro 

    // assert_eq! -> verifica se os dois valores são iguais
    // se não forem -> teste falha com a mensagem 
    assert_eq!(payment.amount, 150.0);
    assert_eq!(payment.currency, "USD");
    assert_eq!(payment.payment_method, PaymentMethod::CreditCard);
    assert_eq!(payment.payment_reason, "Test Payment");
    assert_eq!(payment.status, PaymentStatus::Completed);
}

#[tokio::test]
async fn test_get_all_payments() {
  let pool = setup_test_db().await;

  let new_payment = NewPayment {
        amount: 150.0,
        currency: "USD".to_string(),
        payment_method: PaymentMethod::CreditCard,
        payment_reason: "Test Payment".to_string(),
        status: PaymentStatus::Completed,
    };


    // Cria 2 payments usando um loop
    // `for _ in 0..2` → repete 2 vezes, o `_` ignora o índice
    // ⚠️ PROBLEMA: new_payment precisa de .clone() pois
    // o Rust move o valor na primeira iteração
    for _ in 0..2 {
      payment_repository::create_payment_repository(
        &pool,
        new_payment.clone()
      )
      .await
      .unwrap();
    }

    let payments = payment_repository::get_all_payment_repository(&pool)
    .await
    .unwrap();

    // assert! -> verifica se a condição é verdadeira
    // !payments.is_empty() = a lista NÃO está vazia
    assert!(!payments.is_empty());

    // Verifica se criou exatamente 2 — nem mais, nem menos
    // Isso só funciona porque o TRUNCATE limpou o banco antes
    assert_eq!(payments.len(), 2);
}
````
